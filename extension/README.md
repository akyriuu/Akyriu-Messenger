# Orbit Messenger — Chrome Extension

Chrome Manifest V3 side-panel client for your own NestJS backend. No paid API or third-party messaging service is used.

## Build and install

From this directory:

```bash
npm install
npm run build
```

Then open `chrome://extensions`, enable **Developer mode**, click **Load unpacked**, and select this `extension/` folder. The `dist/` folder is generated by the build, including the service worker bundle. After changes, run `npm run build` and click Reload on the extension card.

Copy `.env.example` to `.env` to change the URLs. If you change host/port, also update `host_permissions` in `manifest.json`.

## Expected HTTP routes

The client currently expects these routes; update `src/sidepanel.ts` to match the actual NestJS controller names and DTOs if yours differ:

- `POST /auth/register` with `{ name, email, password }`
- `POST /auth/login` with `{ email, password }`; response must contain `access_token`, `accessToken`, or `token`, optionally with a `user` object
- `GET /friends` — returns friend records with `id` and optional `name`/`email`
- `GET /friends/requests` — returns incoming requests with `id` and requester/user details
- `POST /friends/request` with `{ email }`
- `POST /friends/accept` with `{ requestId }`
- `GET /messages/:otherUserId` — message history; this route must exist in the backend for history to load

## Expected Socket.IO events

The extension connects with `auth: { token }`, emits `join` with `{ userId }` on connection, emits `sendMessage` with `{ recipientId, content }`, and listens for `message` events. The event names and payloads must match your NestJS gateway; Socket.IO does not create these handlers automatically.

## Notes

- JWT is stored in `chrome.storage.local` to persist the login.
- Configure NestJS HTTP CORS and Socket.IO CORS/transport settings for the extension if the browser blocks requests.
- This initial version does not include notifications or an unread-message badge.
